# EMAIL-E1 transport and templates handoff

Implemented on `kenny/lifecycle-emails`, base963a2d59. Shared workspace: preserved other engineers' auth/billing changes and the unrelated indexing log. No commits, deployment, real provider calls or human emails performed by this engineer.

## Delivered

- Ten pure HTML/plain-text templates in `src/server/services/lifecycle/templates.ts`; all identify Radar/Fairspleet LLC, use the configured app origin, escape user data, and provide support replies. Founder note uses Ekene attribution and team@thally.io. Billing CTAs use the existing `?section=billing` route. Fictional, reviewable drafts in `previews/`, generated by `node --import tsx scripts/preview-lifecycle-emails.ts` without sending.
- `queueLifecycle(q, {type,userId,eventKey,data,sendAt?,businessId?})` inserts encrypted frozen provider bodies inside the caller's transaction. Unique event keys dedupe; guest accounts are excluded. Reset links are not stored in plaintext columns or logs.
- Migration0009 and matching Drizzle snapshot add lifecycle mail, hashed reset tokens and optional onboarding preferences. Existing outbox and legacy mail send behavior are untouched.
- Dispatch uses atomic leased claims plus a deployment advisory lock, password-reset priority, conservative8requests/second,50rows/batch,10second request/body deadline, provider IDs, transient retry/backoff, permanent failure states, and stable Resend idempotency keys/bodies. It refuses retries outside23hours after the first attempt, within Resend's24hour key retention. API acceptance is recorded as `sent`; this does not assert inbox delivery.
- Send-time eligibility suppresses outdated trials, cancellations, end notices, resolved failed invoices, consumed/expired reset tokens, changed recipients, and opted-out founder notes. Reset encrypted bodies are cleared after sent/failed/suppressed. Stub mode never contacts Resend even when a key exists; missing real credentials retain queued mail and log a configuration error.
- The existing worker process starts a dedicated lifecycle dispatcher loop, independent of analysis job slots, scheduler hooks and lapsed-business access. It processes ten-row batches with a one-second idle gap and the existing global rate/replica lock. Missing credentials back off for30seconds. Graceful shutdown aborts the current provider request and prevents further claims; eligibility checks have a ten-second deadline and reset leases before sending when stopped. Optional `userIds` operator/test scope avoids draining unrelated local fixture queues; production omits the filter.
- Signed preference links show a confirmation page on GET; a validated, origin-checked POST disables optional setup emails. Security/billing notices remain enabled.

## Operational notes

The PM identified analysis-slot starvation as a launch risk and authorized the dedicated in-process loop above. No additional service or dependency is required; the old mail job/cron registration was removed. Password resets take priority on every outbox claim, including during launch backlogs. The underlying provider's own quotas and latency still bound throughput. No historical backfill or external campaign is scheduled.
