# YouTube connected-data lifecycle

User requests completed production posting and Google OAuth verification. Implement the API-data lifecycle needed for truthful verification, independently of the urgent OAuth transport hotfix (PR64/main a8956315).

Approved architecture: retention-architecture.md. Preserve owner-authored content, local media and irreversible duplicate-prevention status; remove YouTube-derived profile/upload identifiers and copied references on revocation/deletion. No remote video deletion or new scopes. No production cleanup script invocation as incidental QA.

Acceptance: R1 daily grant/profile checks and bounded global expiry operate regardless of billing/publishing flags. R2 profile and receipt data refresh/delete within 28-day safety bound, stale projection suppressed immediately. R3 disconnect, definitive revocation and soft business deletion remove all scoped API-derived copies and immediately attempt remote revocation, with encrypted retry payload wiped within24h. R4 accepted/uncertain uploads retain opaque no-resend markers enforced through manual/schedule/Autopilot/recovery so cleanup never causes duplicate upload. R5 late remote writes cannot restore scrubbed data; tenant/platform boundaries intact. R6 transient/configuration failures distinguish from revocation; explicit configuration hold prevents posting until validation while hard expiry remains. R7 contact deletion invokes the same trusted scoped callable through a documented runnable dry-run/apply procedure, tested without new account-deletion UI. R8 accurate privacy disclosures ship with implementation; focused tests, independent actual DB/browser QA, Node22 production build and live runtime checks precede readiness.
