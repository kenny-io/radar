# Bounded explanation review repair

Implementation freeze: branch `kenny/media-review-repair`, base `04270aba81ad8dd9bc6ebf7e98dc364762efcace`. Owned changes only `src/server/services/social/media/planner.ts`, `planner.repair.test.ts`, and this note. Other agents' UI/OAuth/QA records remain untouched. No commit, deployment, production database mutation, provider request, or paid narration performed.

A valid failed mechanism or plain-language review now permits **one shared internal revision**, purpose `social.media.revise`, stage `Revising explanation`. The existing business-selected writing model and its normal routing remain unchanged. Initial success still makes exactly three logical AI calls. Mechanism failure uses five calls on successful repair; clarity failure uses six. Reviews fail fast. After correction, both accuracy and clarity must pass again before returning any plan to narration. A persistent defect returns `media_review_failed`; an invalid corrected semantic plan receives useful review-failure guidance. Layout/duration/source errors retain their actionable error codes. Malformed reviewer output, AI refusal, guard failure, budget failure, and timeout never trigger correction.

Revision uses fixed instructions with JSON fields separating the immutable source snapshot, candidate, presentation direction, and diagnostic findings. Reviewer findings are explicitly untrusted diagnostics, not factual evidence or instructions. Source qualifications remain binding; reduced risk must not become a guarantee or invented exclusive mechanism. Revised plans are schema/semantic/layout/duration validated before further reviews, and their source URLs must come from the original supplied source. Bounded verified pages are read once per invocation and reused for revision reviews. The existing material-evidence gate in `sourceFor` is unchanged and remains before planning.

Each real planning/review/revision dispatch retains the same eight-minute admission deadline, guard, priced conservative reservation, and 90-second provider-attempt timeout. The deadline is an admission check, not a new cancellation mechanism. Logical AI requests can contain normal bounded provider retries/failover; each actual dispatch must reserve again. No automatic speech retry was added. Existing beforeAttempt placement outside provider retry handling prevents budget/guard refusal from falling through to another paid route.

Budget: no guarantee that a repair fits the $3/business/day allowance, particularly after earlier retained reservations. Opus 5.5 reserves $0.16 output ceiling per 8,000-token plan/revision and $0.07296 output per review (1,600 requested plus 2,048 provider headroom), plus conservative input `(UTF8 bytes(prompt+system)+16000)*4/1e6`. Failed/uncertain attempts retain their ceilings; another actual retry can exhaust the allowance. Atomic reservation refusal returns the existing tomorrow/allowance error before dispatch. No cap or production counter was changed. Speech needs its own later reservation even when reviews pass.
