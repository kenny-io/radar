## Findings sent immediately to backend and PM

1. **Narration spend reporting omits known estimated cost.** `media/narration.ts` records successful charged_characters but passes `costUsd:null` to recordAiCallNow and never reconciles known estimate. Budget stays conservatively safe, but ai_calls omits speech expenditure. PM clarification: compute/record chargedUnits * verified public rate as an explicit estimate; actual_usd remains null unless actual invoice/account-specific USD is supplied. Do not mislabel estimated public-rate cost as actual charge. Test successful record once, no duplicate cached recording, unknown dispatch keeps reservation and null actual. Current official v4 public rate was checked at$0.08/1000chars; no key-scope expansion is needed for pricing.
2. **Source revision is not authoritative.** `media/index.ts` sourceKey uses pack.source, cached pack.grounding, voice and notes. `requestMediaIntent` retains existing checkpoint.plan for the same key. `planner.sourceFor` rereads the linked article/URL only when no plan exists. Editing a linked Radar article then explicitly preparing again can therefore reuse the old explanation; generateMedia's hash guard still passes. Hash authoritative fetched content/article revision outside locks and clear old plan on change, or explicitly pin immutable snapshot with a visible refresh-source operation that creates a new revision. Regression: same-source repeat reuses, changed linked article + Prepare produces new source hash/plan, old prepared request cannot overwrite newer intent.
3. **Drawing cues are not tied to actual narration inside a scene.** `media/draw.ts` reveals each node at fixed i*0.65seconds, edges at similar index offsets, revisits after elapsed>4. `timeline.ts` aligns scene boundaries/captions only. A long scene reveals every object in its opening seconds independently of when its term is spoken. Add bounded node/edge/revisit narration cues mapped to validated character positions/timestamps; render from those times. This is an approved M4/M5 contract requirement, not a request for another animation framework. Verify real word-to-object introductions, causal movement and revisits against the new Brian recording; caption correctness alone does not prove diagram alignment.
4. **R2 cleanup performs network I/O while holding the global scheduler lock.** `media/jobs.ts` directly awaits collectMediaCache from cron. `index.ts:134–142` opens DB transactions and awaits deleteStoredObject; S3 deletion has no explicit deadline. Up to30candidates can stall all scheduler hooks, including publication/privacy maintenance. Cron should enqueue a durable bounded cleanup job, with per-network abort/deadline and existing reference/lease checks retained. Verify R2 timeout does not block another cron hook and cleanup never deletes attached/current artifacts.
5. **Render concurrency lock needs loss handling.** `media/render.ts` takes a dedicated connection session advisory lock, but does not abort child work when that connection dies. A lost session releases the database lock while the CPU child can continue, permitting a second global renderer. Register connection loss/error handling that kills the child and fails/requeues safely; remove handler/release in finally. A lost render must reuse saved narration and not publish partial files.

Backend was already addressing publication/pack lock-order races found by Q7. This review deliberately did not duplicate that test work or UI/browser QA. Final attach currently locks business, sorted publication rows, sorted pack rows, then generation; retain consistent ordering in request/cancel/retry/cleanup flows after final fix.
