## Implemented contract

- New `RegistryDraftZ` / `RegistryDraft` retain existing Plan metadata, claims, scenes/edges/cues/revisits/narration limits. Global entities are2..48 strict `{id,kind,label}` declarations; scene nodes are strict `{id,state?,values?,units?,illustrative?,claimRef?}` references using unchanged field limits. Per-scene kind/label overrides and extra declaration attributes are rejected rather than stripped.
- Pure `compileRegistryDraft` parses the draft, uses a `Map`, rejects duplicate declarations (`entity_duplicate`) and unknown references (`entity_reference`, scene index), expands references and runs the unchanged `PlanZ`/`validatePlan`. It does not rename IDs, choose a conflicting label, merge actions, rewrite speech/claims, edit cues or reorder/drop relationships. Measured layout and platform duration still run in the planner. Unused bounded declarations do not become a new repair trigger.
- Initial and correction AI requests now use `RegistryDraftZ`, retaining12k/120s, selected business writing model, actual-attempt guard/price/reservation and eight-minute admission deadline. Reviews receive compiled strict Plan, matching rendering. Correction input identifies the raw candidate version and includes that exact raw candidate, immutable evidence and allowlisted diagnostics as separated untrusted data.
- New private recovery version2 stores the bounded raw parsed RegistryDraft before compilation; version1 continues holding legacy Plan. Both versions match only the same source/cap. Existing accepted `checkpoint.plan`, renderer version/cache identity, paid narration/cache and artifacts are unchanged. No public raw-draft exposure or authority was added.
- A valid legacy candidate validates/reviews without another plan or upgrade request. An invalid legacy candidate remains unchanged through the dispatched checkpoint and gets exactly one authored registry correction through the existing shared allowance. That response becomes version2/completed before compilation. A completed or interrupted correction cannot obtain another automatic correction. Explicit owner Retry remains the deliberate reset; source/cap drift and safe Generate reprepare behavior remain unchanged.
- The observed conflicting legacy `fix` identities are preserved in the regression input. The authored correction explicitly distinguishes `fix`/Reproduce first from `addLink`/Add title or nav link; no production helper performs that conversion. Spoken narration and claims are preserved by the compiler. Prompt instructions require structural correction to preserve them unless factual/cue/duration correctness requires supported edits, and forbid hiding different actions as states of a generic entity. Registry structure does not prove semantic correctness: mechanism and clarity reviews remain mandatory.
- Review/correction rubrics explicitly permit neutral term definitions, schematic illustrative actors and source-grounded explanatory scaffolding without invented product facts. Same-scene introduction followed by revisit is valid; recurring entities need not all be highlighted, and `revisit:[]` is valid. Unsupported mechanisms, statistics, exclusive claims, and reader/business outcome guarantees remain forbidden. A title/navigation-link check cannot guarantee readers reach the guide.
- `stubRegistryDraft` is an explicitly synthetic development fixture based on the fixed valid stub; it is never used to normalize a paid legacy candidate.
