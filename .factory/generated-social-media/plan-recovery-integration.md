## Runtime behavior

- `planExplanation(..., maxDuration=180, recovery?:PlannerRecovery)` accepts `{sourceHash, checkpoint?:PlanningRecovery, save(value):Promise<void>}`. It independently verifies `hash(source)`. Initial and revised `PlanZ`-parsed candidates are capped at64KiB and awaited into the private lease-bound checkpoint before semantic/layout checks. No candidate becomes a reviewed plan, public notes, recommendation, artifact or narration authority.
- One shared durable allowance covers known semantic, measured layout, duration, mechanism and clarity defects. Typed `PlanningValidationError` carries a fixed code/phase and optional scene index while preserving all existing validation requirements. Revised candidates undergo complete validation and both reviews. Persistent defects stop; malformed review/schema, model/provider refusal, guard, budget, unallowed source, missing fonts/native/runtime or unknown errors never trigger correction.
- Recovery records v1/sourceHash/maxDuration/candidate/repair `available|dispatched|completed`. The `dispatched` marker is awaited before the correction request; `completed` candidate is saved immediately on response, before validation. Automatic resume reuses matching candidates, cannot repair a completed correction again, and stops unknown dispatched corrections with `media_plan_interrupted`. Deliberate Owner Retry resets the same-source/cap candidate allowance; authoritative source/cap is checked again on run before it can be used. Text completion before durable persistence still has an unavoidable uncertain interval; no exactly-once text billing claim is made. Speech uncertainty behavior is unchanged.
- Accepted `checkpoint.plan` is written only after validation+both reviews, with explicit `planSourceHash`/`planMaxDuration`, then unreviewed recovery is cleared. A changed source/cap atomically clears the old plan, bindings and mismatched recovery before replacing the source snapshot. Legacy unbound plans are never used for new narration. Existing finished attachments remain usable.
- Generate transparently re-enters preparation for legacy, changed-source/input/cap plans using existing durable intent, chosen formats, options and `generateAfterPrepare=true`. Transaction-time stale state returns a signal; preparation occurs after releasing locks. Existing attachments remain visible. Re-preparing identical legacy content can transfer newly reviewed bindings to a same-plan derived cache while retaining cached paid audio/artifacts.
- Plan-only Retry immediately projects `preparing/Reading sources`, and the running planning stages remain `preparing`, enabling existing real Writing/Checking/Revising labels. No UI component or whitelist was changed.
- Known diagnostic fields are private phase/code/scene only. Unknown exceptions retain only up to three allowlisted relative media-module line/column frames. `planningDiagnostic` additionally records safe failures occurring before a candidate exists. No raw exception, source, provider body or reviewer echo enters diagnostics/public failure copy. Public review failure text is fixed and actionable. Review diagnostics remain source-untrusted data in the correction JSON, not instructions/evidence.
