# Divergences — Social Marketing (library, generate flow, Suggest ideas, pack view, automatic generation)

None of the known risks in the handoff `DIVERGENCES.md` (#1–#12) belong to this area. Principle #1 holds: there is no posting code path anywhere in the social area. Packs are only stored, copied (`copiedAt`) and downloaded.

| Area / screen | Designed behavior | What was built instead | Why | User-visible? | Status |
|---|---|---|---|---|---|
| Generate flow → generation failure | No failure state: the prototype always succeeds after the timed rows | If the `social.generate` job fails, the modal goes back to the step it was on and shows the error in the flow's existing red error line (same style as the validation messages). Copy: "Radar couldn’t read that page. Check the link and try again." when an article URL can't be fetched, otherwise "Radar couldn’t finish this. Try again." | Real fetches and model calls can fail. This reuses an existing element and adds no new UI | Yes (new copy) | Needs approval |
| Suggest ideas → failure | No failure state | If the ideas call fails, the list area shows "Radar couldn’t finish this. Try again." in the empty-state style (`small sub`). Reopening the tab retries | Model or database errors are possible | Yes (new copy) | Needs approval |
| Pack visual headline for Article URL packs | The visual's headline is `pack.source.label`, which is the raw URL for URL packs | URL packs draw the fetched page title on the visual (stored as `pack.headline`). The pack name is still `shortHead(url)`, as in the prototype | Drawing a raw URL on a brand image looks broken | Yes (image content only) | Needs approval |
| Generate flow → Image style previews | The preview tiles use hard-coded Fieldnote copy ("Bill what you work", and "3x faster invoicing" for Infographic) | All five tiles use the business's first differentiator, falling back to the business name. The Infographic tile shows the template's default large figure ("3x") when the headline has no number | Fixed Fieldnote copy would be wrong for every other business (README §2.2: no fixtures) | Yes | Needs approval |
| Suggest ideas → keyword with no volume yet | Not specified (fixtures always have volume) | The metric line reads "“{kw}” · — searches a month" (the shared `fmtN` dash for missing data), and the idea scores 0, so it ranks last. Volume normally fills in within minutes (`keywords.estimate`) | "Not collected" is not zero (README §2.5 #4) | Yes (rare) | Needs approval |
| Suggest ideas → query→page map ("Links to", "You rank without a page written for it.") | "The user's page that ranks for the query" | `gsc_rows` stores the query and page dimensions separately, not query×page. A query maps to the user's page whose title, H1 or path contains at least 2/3 of the query's content words (stemmed), preferring pages with Search Console impressions. Keywords use the same match over crawled and ranking pages. No match means no "Links to" line and "You rank without a page written for it." | Data isn't stored per query×page. Adding a `query+page` row kind to the GSC sync (performance area) would let this become exact | Maybe (which path shows) | Logged |
| Suggest ideas → Search Console state | `gsc` = status `connected` | Status `connected` or `error` (connected, but the latest sync failed), as long as synced rows exist. This drives the loading copy, the "· not ranking" suffix and the "Search Console not connected" footer | The synced data is still the user's real data. This matches `Workspace.measured` | Minor | Logged |
| Suggest ideas → KD missing | Prototype JS: `null <= 25` is true, so a null KD counted as "easy" | A null KD is neither easy nor hard: no " Few sites compete for it." / " Competitive in search." suffix, and a ×1 multiplier | Never imply data Radar doesn't have | Minor | Logged |
| Suggest ideas → branded queries | "Skip branded queries" | A query is branded when it contains the business name (with or without spaces) or the domain label (e.g. "fieldnote") | Spec gives no rule | No | Logged |
| Suggest ideas → angle titles | One LLM-written angle per candidate | Candidates are scored first. Only the top 30 by score are sent to the writing model, in one call. The model may return no title (topic doesn't fit). Then a priority keyword falls back to `“{kw}”: what {segment} get wrong` and other candidates are skipped, exactly as in the prototype | Cost and latency. Lower-scored candidates can't reach the visible list | No | Logged |
| Suggest ideas → "Ties to" verification | Pick the fact with the LLM and verify it | The model proposes a fact ref. It is kept only if (a) it shares a non-generic whole word (stemmed, ≥ 4 letters) with the angle or query, or (b) a second, strict yes/no model call confirms it. Otherwise the line is omitted, and if the check call fails the fact is omitted too. Fallback angles use the prototype's word-overlap `profFact`, with stemming and generic words ignored | README §2.5 #6: a wrong fact is a bug | No | Logged |
| Suggest ideas → results cache | Prototype recomputes on every open (1.5 s fake load) | Results are cached in memory per business for 6 h, keyed on profile, keywords and GSC data date. The loading state shows for at least 600 ms to avoid a flash | Avoid repeated model calls when switching tabs | No | Logged |
| Packs → platform order | Tabs and thumbnail list follow the order the platforms were picked | Same, using a stored `order` array, because Postgres `jsonb` doesn't keep object key order. Older packs without `order` use the canonical platform order | Storage detail | No | Logged |
| Generation rules enforcement | Per-platform rules | Each draft is checked: X ≤ 280, Reddit has no links and has a disclosure, Quora has "Q:" + "Short answer:" + a disclosure when the product is named, LinkedIn has ≤ 2 hashtags, no competitor names. A failing draft is regenerated with the problems as feedback, up to 3 attempts. Then hard rules are enforced deterministically: X is trimmed at a sentence boundary, Reddit links are stripped and a disclosure is appended, LinkedIn hashtags are capped, any non-source URL is removed, and sentences naming a competitor are dropped unless the source itself is about that competitor (e.g. an "alternative" query) | Guarantees the rules regardless of model behavior | No | Logged |
| Generation → links | Not specified except Reddit | Reddit: no links ever. Other platforms may include only the pack's own source link (the article URL, or a published Radar article's URL), at most once | Prevents invented or third-party links | No | Logged |
| Images | `drawVisual` canvas | Every post's visual is rendered server-side at the exact size (LinkedIn/Facebook/Quora 1200×628, X 1200×675, Reddit 1200×900) via `services/images.ts` and stored as `post.imageUrl`. Photography and Illustration use the image model when configured, else the brand template (core divergence). "Custom direction" renders as Illustration guided by the custom text (the prototype also stores it as Illustration). The live template shows while `imageUrl` is missing or re-rendering | Real generated assets for download | No | Logged |
| PackThumb | Live template at 1.6:1 | Same for template styles. When the post has a model-generated photo or illustration, the stored image is shown cover-cropped to 1.6:1 | Show the real image | No | Logged |
| Regenerate text | `genText` variant v+1 | Re-runs the writing model with the pack's stored grounding (the URL isn't re-fetched) and the previous text as "don't repeat this", v+1 | Real generation | No | Logged |
| Automatic generation → schedule | Cron at `auto.time` on the selected days | A minute cron checks every business with `auto.on`. It fires in the hour after `auto.time` (business timezone) on the selected days, so a short worker outage doesn't skip a day. It is idempotent per business per day (`once`). Days and platforms are saved in week and canonical order | Robustness | Days list order only | Logged |
| Automatic generation → source choice | "Most recent published or approved article, or else a Suggest-ideas top idea" | The most recent unused article: published first (by date, newest first), then scheduled/approved entries dated within the next 7 days. Otherwise the top Suggest-ideas idea not already used as a pack. If neither exists, nothing is created that day. No toast is sent when an auto pack is created (none designed) | Spec leaves "used" and "approved" open | No | Logged |
| AutoModal → toast timing | Toast immediately on Save | The modal closes immediately (optimistic). The toast appears once the server confirms, and on failure the error toast shows instead | Don't confirm a save that failed | No | Logged |
| Pack view → "Copied {ago}" | Computed at render | Re-renders every 30 s so the relative time stays current | — | No | Logged |
| Article URL fetch | — | Server-side GET with the crawler user agent. Redirects are followed (max 4), with a 12 s timeout and a 2 MB cap. An SSRF guard allows only public unicast IPs (checked at DNS lookup and for IP literals) and only http/https on standard ports. The readable text is extracted (title, description, article/main text, ≤ 3,500 chars). The dev stub never touches the network | Security | No | Logged |
