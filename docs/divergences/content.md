# Divergences — Content Calendar, Article workspace, Drafting

| Area / screen | Designed behavior | What was built instead | Why | User-visible? | Status |
|---|---|---|---|---|---|
| Article → Sources (handoff #6) | "Remove any source and its claims are flagged in the draft." No removal control or flag styling designed | Each source row gets a small ghost ✕ icon button (Edit mode only); a removed source is dimmed with its title struck through and the ✕ becomes ↶ (restore). Claims tied to it (sentence → source index stored at draft time) get a subtle `--signal-wash` background with a 1.5px `--signal` underline inline in the draft, tooltip "Its source was removed" | The footnote promises it, but neither the control nor the flag style was designed. Used the smallest affordance possible | Yes | Needs approval |
| Article → embedded video | Placeholder tile with a duration badge in the bottom-right corner | A real `youtube-nocookie.com` iframe with "{title} · YouTube · {channel}" credit. The duration badge was dropped because it would sit over the player's fullscreen and settings controls. The remove ✕ stays in Edit mode. The "VIDEO PLACEHOLDER" label is removed (README §2.4) | Real embed | Yes (badge) | Needs approval |
| Article → Media → YouTube list | Thumbnail tile with a gradient | Real `i.ytimg.com` thumbnail behind the same play icon. Three skeleton rows show while suggestions load. When YouTube isn't configured (no `YOUTUBE_API_KEY`) or returns nothing, the whole "Relevant YouTube videos" section is hidden | Real data; the empty and loading states aren't designed | Yes (loading/empty) | Needs approval |
| Article → video suggestions | Suggestions from a template | YouTube Data API `search.list` (q=keyword, type=video, videoEmbeddable=true, order=relevance, publishedAfter = 2 years ago, regionCode/relevanceLanguage from the calendar market and language), then `videos.list` for duration, views and embeddable/public status. Keeps 90 s–45 min videos, drops competitor channels, takes the top 3. The one-line "why" comes from the writing model, grounded only in title, description, date, views and the outline, with a deterministic fallback. Cached on the article for 7 days | Spec §7 | No | Logged |
| Dev stub videos | n/a | In `RADAR_DEV_STUBS=1` the ids are `stub-…` and the iframe uses a sandboxed local `srcdoc` ("Video embed (dev stub)"), with no network call | Brief: stub mode must not embed real ids | Dev only | Logged |
| Calendar → Research phase 4 | "{n} queries · 16 months" | "{n} queries · {m} months", where m = the distinct months of query data actually synced (16 after a full backfill). While syncing, or after an error that kept data, the phase is labeled "Pulling Search Console queries" and uses the partial data | Real counts; avoids claiming 16 months mid-backfill | Yes (copy only while partial) | Needs approval |
| Calendar → Setup modal | "Website content · 18 articles" | "Website content · {B.site.articles} articles". If the site was never analyzed (null), it shows just "Website content" with a mute dot, never "0" | Not collected ≠ zero | Rare | Needs approval |
| Calendar → Research → phase pacing | Prototype phases took ~1 s each (sleep) | Each real phase shows for at least 520 ms, so fast phases (cache hits, stubs) don't flash past. Every result string is real | UX pacing, no fake data | No | Logged |
| Calendar → Research → failure | No error state designed | On final failure, the job toasts "Radar couldn’t finish this. Try again." (generic AI error copy) and the screen goes back to its previous state | Missing design | Yes | Needs approval |
| Calendar → keyword expansion | Provider related/questions | Provider `related()` per target keyword (priorities first), plus Search Console queries (non-branded, ≥20 impressions), plus customer-phrasing ideas from the writing model. Those ideas are kept **only** if the keyword provider reports search volume for them | More candidates in thin niches; nothing rests on the model's guess | No | Logged |
| Calendar → "too hard" | "kd well above what the domain can win" | Ceiling = the highest KD among queries the site already ranks top-10 for (GSC, estimated), else the median KD of the target keywords; +15 headroom, clamped to 30–75. Candidates above it are dropped unless the site already ranks top-20 for them. Off-topic and duplicate clustering is done by the writing model with index-validated JSON | Spec leaves the threshold open | No | Logged |
| Calendar → refresh candidates | Pages at positions 8–20 with high impressions or low CTR | Last-28-day page rows at positions 8–20 with impressions ≥ max(100, p75) or CTR < 60% of the expected CTR (2.5% at 8–10, 1% at 11–20). Up to 5, spread every 5th slot. The keyword is the overlapping query with the most impressions, because page+query rows aren't stored | GSC rows are stored per dimension, not per page+query | No | Logged |
| Calendar → relevance | Sentence citing the real reason | The model gets per-topic facts computed from data (GSC numbers, keyword-list membership/priority, buyer-need or offering token overlap) and must cite only those. Any number not present in the facts → a deterministic sentence from the strongest fact is used instead | Principle #6 | No | Logged |
| Calendar → Replace topic | Sheet closes after replacing (prototype swaps the id) | Kept as designed: the sheet closes and "Topic replaced" offers Undo. The entry keeps its id and date on the server; Undo restores the previous topic and outline | — | No | Logged |
| Calendar → drag onto a queued day | Swap dates | If the target day holds a scheduled/published entry, the dragged entry moves there and the locked entry stays put (no swap) | Locked entries must not move | Rare | Logged |
| Drafting → toasts | “{title}” is drafted and ready for review. / {n} drafts are ready for review. / autopilot "… and queued to publish." | Autopilot copy is read as “{title}” is drafted and queued to publish. / "{n} drafts are ready and queued to publish." Single review toasts carry **Open** → /article/{id}. Multiple carry **Review** → Calendar list filtered to Ready for review. Drafts started by the user ("Draft now", "Rewrite from brief") toast "Draft ready. Edit anything, then approve." (§6 Toasts). Titles over 40 characters are cut with "…" | Interpretation of "…" in the spec | Yes | Needs approval |
| Drafting → failure | Not designed | After 2 attempts the entry goes back to `approved` ("Draft now" is available again), the cron retries the next day, and the toast "Radar couldn’t finish this. Try again." appears | Missing design | Yes | Needs approval |
| Drafting → schedule | D−1 at publish time | Every minute, once `blog.time` has passed in the business timezone, approved entries with date − 1 ≤ today start drafting. A topic approved later that day (for tomorrow) drafts right away. Articles approved "without publishing" (already written) are never redrafted | Edge cases of the D−1 rule | No | Logged |
| Drafting → autopilot | "drafts and schedules one article a day without review" | With autopilot + acknowledgment + a connection, the cron auto-approves the single proposed entry dated tomorrow (only when nothing else is on that day), once per day. On finish, drafts go to `scheduled` unless paused (then `review`) | Interpretation | No | Logged |
| Article → statistics validation | Never invent statistics | Statistic-like numbers (%, currency, multipliers, or ≥10 excluding bare years) in the draft must appear in the source notes, brief or profile. Offending sentences are rewritten without the number by a fact-check pass, or dropped. The streamed preview may briefly show a number that the saved draft doesn't contain | Validation runs after streaming | Marginal | Logged |
| Article → citations | "Radar cites sources inline" | The model writes `[n]` after sourced sentences. Markers are stripped from the body and stored as `claims` (sentence → source); the source is also named in prose where natural. Rendering the markers as links at publish time is up to the publishing renderer | Block[] is plain text | No | Logged |
| Article → research sources | Web search + user's own pages | Research-model web search (structured: title, url, use, verbatim notes). When the provider returns citations, only URLs from those citations are kept. Competitor and own-domain URLs are excluded. Plus up to 3 of the user's crawled pages and a "Search Console — queries for “kw”" source when GSC has matching queries | Hallucination guard | No | Logged |
| Article → SEO on redraft | — | "Rewrite from brief" regenerates body, sources and claims but keeps SEO title/meta/slug, image and videos. A first draft keeps any SEO or brief fields the user edited beforehand | Don't overwrite edits | No | Logged |
| Article → hero image | Canvas templates | Server render via `renderImage` (1200×628) stored at `img.url` with `img.urlKey = style:seed`. If the style/seed changes, the live template shows until the new render lands (style change re-renders on save; Regenerate = seed+1 + render) | Stale-image guard | No | Logged |
