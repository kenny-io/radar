# Divergences — Publishing (blog connectors, publishing settings, scheduler/publisher)

| Area / screen | Designed behavior | What was built instead | Why | User-visible? | Status |
|---|---|---|---|---|---|
| #8 Timezone select (BlogConnect Mode step) | The prototype lists 4 timezones | Full IANA list from `timezones()` (the prototype's 4 lead the list). Settings → Schedule should use the same helper (SettingsPage). | A full list is needed for real businesses | Yes | **Closed** — done as the known risk proposed |
| #10 Next.js connector "published" | Published = PR opened, or PR merged? | **Published = pull request opened.** `publishedUrl` is the PR URL, so "View post" opens the PR. No merge polling. | The live URL depends on the user's site routing and deploy, which Radar can't know; a PR closed without merging would still read "Published". Merge polling could be added later (cron on `GET /pulls/{n}`). | Maybe | Needs approval |
| BlogConnect → Webhook signing secret | Read-only masked field `whsec_7Kq2…f91A` | Masked exactly as designed. While **creating** the connection, focusing the field reveals and selects the full secret so it can be copied (it's generated server-side and returned once). After saving, only the masked form is ever shown; a new secret = disconnect and re-add. | The user needs the full secret to verify signatures; the design has no other way to get it | Yes (reveal on focus) | Needs approval |
| BlogConnect → Test connection failure copy | "401 Unauthorized — check the credentials" / "The authorization expired. Reconnect and try again." | Same copy with the **real** status, e.g. "403 Forbidden — check the credentials", "404 Not Found — check the credentials". OAuth-only platforms (Webflow, Notion, Wix, WordPress.com) show the "authorization expired" copy for 401/403. When the host can't be reached at all: "Couldn’t reach {host} — check the URL" (new copy). | Real failures aren't always 401; a network failure has no status code | Yes (new network copy) | Needs approval |
| BlogConnect → Webhook test | "test draft created, then deleted" | A webhook has no draft: the test sends a signed `radar.test` event; any 2xx passes (success copy unchanged). | No draft concept on the receiving side | No | Logged |
| BlogConnect → Next.js test | Draft created then deleted | Creates a branch from the default branch (`radar/connection-test-…`), then deletes it (proves push access). | A branch is the Git equivalent of a draft | No | Logged |
| BlogConnect → Framer picker | Static options (Blog, Articles) visible immediately | Options are the project's writable CMS collections, listed from the Framer Server API once Project URL and API token are filled (empty "Choose…" until then). | BlogConnect → OAuth picker options | Prototype fixtures | Real targets from each platform (Webflow collections across sites, Notion databases shared with the integration, the Wix site the app was installed on, Shopify blogs, WordPress.com sites the account can publish to). The first option is preselected, as in the prototype. If listing fails, the test row shows the failure copy. | Real data | No | Logged |
| BlogConnect → editing secrets | Prototype re-renders saved fields | Password/API-key fields are blank when editing (never sent to the client); leaving them blank keeps the stored secret, and they don't block **Test connection**. | Secrets are never returned to the client (README §4) | No | Logged |
| BlogConnect → Save/Continue spinners | No spinner on Add connection / Save | `Btn loading` while saving (01-screens §13: every async action shows a spinner). | Global rule | No | Logged |
| BlogConnect → OAuth popup failure | Not designed | Closing the popup silently returns the button to "Sign in with…". Any other OAuth error toasts "Radar couldn’t finish this. Try again." Missing OAuth app credentials (prod) → the popup reads "Access wasn’t granted" and the same toast. | Missing state | Yes | Needs approval |
| Settings → Publishing → connection status | "● Connected" or "● Paused" | Also "● Needs reconnecting" (bad tone) when the platform last rejected Radar's credentials (401/403 on publish). Cleared by a passing test or publish. | Otherwise a broken connection reads "Connected" | Yes | Needs approval |
| Publisher → retries | Retry up to 3 times with backoff, then failed | Up to 3 retries (30 s, 2 min, 8 min) for **transient** failures only (network, 408, 409, 429, 5xx). Other 4xx (e.g. 401) fail immediately — retrying can't fix them. The draft created on the platform is remembered (`calendar_entries.publish_remote`) so a retry never duplicates it. | Faster, honest failure surfacing | No | Logged |
| Publisher → failure record | `publishError {http, message}` | `{ http, message, platform }` where `message` is the status line ("401 Unauthorized"), `platform` the label ("Ghost"); network failures use `http: 0`, message "no response from {host}". Content/Dashboard render "{platform} returned {message}". No toast on failure (the article banner and dashboard issue are the designed surfaces). | Matches the article banner copy | No | Logged |
| Publisher → refresh entries | Not specified | WordPress, Ghost and WordPress.com update the existing post in place (found by the slug at the end of `entry.url`) instead of creating a new one; other platforms create a new post. Webhook payload carries `mode`/`refresh_url`; Ghost/Next.js/webhook get `canonical_url` = the existing URL for refresh entries. | Refreshing should not create duplicates | No | Logged |
| Publisher → canonical URL | Payload includes the canonical URL | For new posts the platform's own URL is canonical (we don't set one); refresh entries carry the existing page's URL. | Setting a guessed canonical can de-index the post | No | Logged |
| Publisher → no connection | — | The scheduler holds scheduled entries for businesses with no connection (e.g. after disconnecting the last one); `publish.now` errors "Connect your blog first." | Nothing to publish to | No | Logged |
| Publisher → outbound links | `applyApprovedOutboundLinks` before sending HTML | Applied to the HTML payload (all platforms except Next.js). The Next.js MDX body and the webhook `markdown` field don't include them. Loaded at runtime from `src/server/services/backlinks/outbound.ts` and skipped if absent. | The helper works on HTML | No | Logged |
| Publisher → article furniture | — | Embedded videos get the editor's caption ("{title} · YouTube · {channel}") plus a "Watch on YouTube" link; citations get a "Sources" heading.
